# 测试计划与验证边界

## 可执行自动化

- `npm --prefix frontend test`：配置白名单、日期/用户时区、23/25 小时夏令时日、包含式结束日、缺失/无效日期、父子环、依赖方向、估算、XSS 转义、同源路径、严格 ID、串行分页/截断/空页/取消/权限撤销。
- `mvn -B -DskipTests=false clean package`：完整前端构建、Java 编译、JUnit 权限与 REST 测试、P2/OSGi 打包。
- `npm --prefix frontend run test:browser`：真实锁定 Community 版在无界面 Chrome 中运行；三个独立实例、缩放、销毁、A/B 会话个人偏好、重新打开/新浏览器保持、只读、XSS、权限错误清空、配置保存、根路径和 `/jira`。

浏览器测试使用本地模拟 Jira REST/AO 合同，不代表真实 Jira ACL、UPM 或 AO 数据库验证。Java 测试使用官方 10.3.18 API 加服务 mock，不代表集群或真实安装验证。

## 必须在 Jira 10.3.18 补做

设计文档 TC-01 至 TC-22 是正式验收基线。测试数据至少包含 admin/A/B、两个 Browse 权限不同的项目、A/B 私有及双方共享 Filter、两个 Dashboard、三个 Gadget、Issue Security 和跨月/DST/异常日期任务。

1. UPM 安装、启用、禁用、卸载和重装；确认目录、Soy、AMD、REST v2、安全注解、Spring 服务导入、AO migration 均正常，记录每个节点启动日志。
2. 对照 PortletConfiguration 验证 getGadgetId；跨 Dashboard 和非本插件 Gadget 的偏好 GET/PUT/DELETE 均拒绝。A 不得读取/覆盖 B 的个人视图，不得向请求注入 userKey。
3. 仅有共享 Dashboard 浏览权限的 B 可以修改自己的视图；不能保存共享配置；固定模式不能 PUT 私有覆盖。
4. 私有 Filter 与 currentUser() JQL 在实际查看者身份下求值。撤销 Filter、Browse、Issue Security 后刷新必须移除旧内容。匿名/停用/无许可/Session 失效不得显示数据。
5. 正负 XSRF 测试：同源 JSON 成功；跨源、无头、简单表单、伪造 no-check、不同 host/port 失败。反向代理 root 与 `/jira` 均正确，确认本地策略是否另要求 Jira XSRF token。
6. 两个浏览器/两用户/两个节点同时写个人偏好，确认唯一键生效、集群锁有效，无重复行；节点切换后状态一致。真实 AO 创建、重复 enable/migrate、升级与回滚不丢数据。
7. 在实际办公 PC 测量 100/500/1000 Issue、1/3/5 个 Gadget 的首屏时间、长任务、内存与请求数。不要把 mock 的速度当作生产指标。
8. 验证日期字段的项目上下文、自定义 Date/DateTime schema、Jira 用户时区、CSP、代理和中文/英文/Linux/Windows 浏览器表现。
9. 同一 Gadget 连续切换筛选器、缩放、刷新、保存失败和网络超时；旧请求不得恢复旧数据、重复实例或写回旧选择。

## 当前结论

当前版本构建产物与验证记录见 `FIXES-1.2.1.md` 和 `validation/*1.2.1*`；`DELIVERY.md` 保留首版历史。真实实例验证须逐项记录范围，不将 mock、编译成功或 API 签名核验等同于完整兼容认证。

## 1.2.0 Jira 同步验收

1. 界面无计划选择、新建、复制或私有副本入口；旧 `/plans` 路由不可用。原始任务仍可浏览，人员多选仅控制显示。
2. 仪表盘所有者 A 可编辑，查看者 B 只读。B 伪造同步请求也拒绝；A 没有项目编辑/分配/截止日期/评论权限或字段不在编辑界面时，明确报告 Jira 校验失败。用无 Jira 编辑权限的仪表盘所有者再测一次。
3. 选择可写自定义开始日期与截止日期；created/updated 或同一字段不得写回。覆盖 Date/DateTime、中文/英文日期格式、用户时区与 DST。
4. 自动排期先计算不写 Jira；应用后打开 Jira 单子检查原始预估、剩余预估、已耗工时、日期和负责人，再刷新仪表盘确认一致。覆盖 h/d/w、同日 6h+2h、小任务整项换日、多日大任务、周末、节假日、补班与锁定任务。
5. 双击条编辑预估和开始日期，拖动左右平移，拉伸改变预估；同一人员的后续任务及真实依赖顺移，已完成任务保持。连线随日期和人员筛选更新。原任务预估为空、负责人为空时给出可操作提示。
6. 备注显式新增 Jira 评论，原有评论可读；刷新后通过 Jira 评论接口核对。校验失败不新增评论，网络结果未知不自动重复提交。
7. 两窗口/跨节点同时修改同一 Gadget 或同一 Issue；覆盖版本/更新时间冲突、同步期间撤销权限、原生 Jira 同时编辑、Jira 中途异常、AO 元数据保存失败与网络中断。分别核对已保存、失败、未执行的真实任务值，不把部分成功当作整批失败回滚。
8. 升级自 1.1.0 时不再使用 PLAN/PLAN_TASK；个人视图保留，SCHEDULE 保存排序/版本, 全局日历存于 WORK_CALENDAR；停用或回滚插件不会撤销 Jira 修改。

## 1.2.1 回归

1. Target start/end、Date Picker、DateTime 各验证显示、拖动和拉伸；旧 created/updated 映射显示具体原因，经修正启用自动排期。类型不支持、字段删除、起止相同、字段不在编辑界面均明确拒绝。
2. 人员搜索匹配姓名和账号；状态匹配项目自定义状态。复选、全选、清空和空结果正确，两个条件取交集，未排期列表同步过滤，不写 Jira。筛选隐藏父任务后子任务仍可见。
3. 展开浮层不改变工具栏高度，不遮挡触发按钮；Escape、外部点击及 Tab 离开关闭，多个 Gadget 的选择不串用。

## 1.3.0 人员、全局日历与布局回归

1. 多人员任务以姓名分组；组内拖动及上下移动顺序保留在提交正文中；跨人员拖动不改负责人。改负责人后重新归组。
2. 100 人可分配列表通过同一控件输入一个字符匹配；分页、键盘选择、Escape、空结果、网络错误和未选中搜索文字的校验正确。
3. 两个 Gadget 共用全局例外日期；排期弹窗没有工作日表单。管理员可保存，普通用户只读，伪造 PUT 返回 403。
4. 日期合法性、至少一个工作日、节假日/补班冲突和旧版本拒绝。预览后修改全局日历，再应用不得写入 Jira；服务端忽略伪造客户端日历。
5. 1440、800、480 像素宽度下任务行控件留出焦点轮廓间距，控件不相交或溢出；浮层搜索不被列表滚动裁切。
6. 回归原有拖动条、拉伸、双击评论、实际更新时间并发保护、部分失败刷新及取消加载。

自动化使用本机 Chrome 和模拟 REST，以及 Jira API mock 单测；真实 AO 升级和 UPM 启用仍需安装新 JAR 后验收。

1. 连续拖动和拉伸, Jira 日期/估时及后续任务实际保存, 不调用整个 Gadget 加载或 Search/field/myself/personal, 图表和工具栏 DOM 实例保持相同。
