# 1.2.2 排期并发误报修复

本地 Jira 10.3.18 只读核验发现：TEST-6 的任务详情 updated 为 `2026-10-27T04:37:15.135+0000`，搜索接口却返回 `2026-10-27T04:37:15.000+0000`。上一版从搜索结果取得毫秒令牌，再与实际任务时间严格比较，产生 135 毫秒差异，因而在无人修改时也报冲突。

新版本从实际任务批量读取可编辑字段及完整更新时间，一起初始化编辑稿。用户修改人员、估时、日期或顺序不会改动这份原始时间令牌。预览和保存仍严格比较完整毫秒，包含同一秒内真实变更；不会通过时间取整或保存前强行刷新令牌来绕过并发校验。

产物为 `target/filter-gantt-gadget-1.2.2.jar`。用户自行上传更新，刷新仪表盘再打开自动排期。无需重建容器。本次未上传新包，也未更改真实 Jira 任务。

验证包括实际任务完整时间与字段读取、浏览权限和请求字段白名单、同秒并发拒绝，以及模拟 Jira 搜索索引丢失毫秒后修改人员/估时并成功同步的浏览器回归。最终构建与测试记录见 `validation/*1.2.2*`。

61 项后端测试、16 项前端单测、25 项最终 JAR 资源浏览器回归通过。安装包 965779 字节，SHA-256：`4AC28A6D691B8F982A0531D6505158BF3922C866DD9794F55040DAF0B598577A`。真实实例仅核验了读取接口的时间差异，新版本写回仍待用户安装后验证。
