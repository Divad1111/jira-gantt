# CI 浏览器测试等待条件修复

## 产生原因

切换时间刻度会异步保存个人偏好并重新加载图表. 原拖动测试仅等待提示包含 "同步到 Jira", 该文字可能属于旧界面或 "正在同步到 Jira". 在图表被移除、重新建立期间读取位置, 得到 null, 随后访问 x 导致测试失败. 本次 GitHub 日志为 36 项通过、1 项失败, build 任务失败因此阻止依赖它的 release 任务执行.

## 解决方案

1. 自动排期应用后等待可编辑状态恢复, 再执行下一步.
2. 切换刻度前监听实际 source 响应, 响应完成且自动排期按钮可用后再定位甘特条.
3. 移动和拉伸后等待同步核实完成, 验证条和拉伸手柄可见、位置非空.
4. 在该用例中主动阻塞 source 响应, 验证加载期间按钮禁用, 再放行数据. 不依赖固定睡眠、重试或跳过测试.

## 测试要点

切换刻度后拖动、拉伸及 Jira 保存断言; 延迟 source 响应时禁止提前操作; 同步完成再调整下一次; 自动排期辅助流程和其余浏览器用例回归.

本地完整 37 项浏览器测试全部通过, 包含受控阻塞的失败场景回归. 实际结果见 [浏览器回归记录](validation/browser-ci-readiness-fix.txt). 本地使用 Windows Chrome 和模拟 Jira REST, 未执行 GitHub Linux runner. 无运行时代码或 JAR 内容变更, 无需本地重新打包.

## 修改清单

浏览器自动化的同步等待条件、受控延迟回归和验收说明. Release 任务继续要求全部测试通过.

## 成因标注

引入方式：历史bug[优化开发完就存在]
