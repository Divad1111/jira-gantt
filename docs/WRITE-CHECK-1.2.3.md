# 1.2.3 日期未写入但提示成功

实际 TEST-6 的 Target start/end 为空，原生 editmeta 中也没有这两个字段。Jira 10.3.18 默认 IssueService 校验和更新只处理编辑界面中的字段，可能忽略没有加入界面的字段并返回有效结果。插件仅判断 isValid，导致把没有落库的排期显示为同步成功。

已在本地 Jira 的 `TEST: Project Management Edit/View Issue Screen` (id=10001，仅 TEST 项目使用) 添加 Target start 和 Target end。随后重新读取 TEST-6 的 editmeta，确认两个字段均具有 set 操作。此变更仅增加编辑界面的字段，不修改任务内容，也不更改项目权限。当前已打开的排期稿可以重新计算并应用；已完成任务仍不重新排期。

1.2.3 增加以下防护，保留原生权限及编辑界面检查：

- 预览时检查发生变化的日期是否参与 Jira 字段校验，未参与则明确提示加入编辑界面，不开始批量保存。
- 应用时再次校验；日期的预期值从已通过原生转换的任务对象读取，兼容自定义字段表单参数。
- 更新后重新读取任务日期，只有与预期一致才标记该任务已同步。返回成功但没有持久化日期时报告失败，停止后续任务，不保存成功的排期元数据；提示其他字段可能已经保存。
