# 1.2.1 日期编辑与筛选修复

截图中的拖动、拉伸与自动排期共用同一可编辑判断，因此字段映射无效时三项同时禁用。上一版后端只接受普通日期与日期时间，遗漏 Jira 已安装的 Target start / Target end；旧配置还可能保留创建日期或其他失效字段，前端提示没有清楚区分具体原因。

本次支持 Target start / Target end 的实际 Data Center 日期类型；保留当前用户的 Jira 权限和原生编辑校验。失效配置显示开始/结束字段及原因，并提供“选择排期日期字段”入口。创建日期和更新日期仍由 Jira 维护，不能作为写回目标。编辑配置时选择两个不同的可写日期字段，保存后可以拖动与拉伸未完成任务，自动排期也会启用。已完成任务保持只读。项目编辑界面也须包含这些字段，原生校验失败会显示错误。

人员筛选改为右侧紧凑下拉浮层，可以输入姓名或账号匹配后复选；支持全选、清空和空结果提示。新增同样的状态多选，可搜索待办、进行中、完成或项目自定义状态。两项条件取交集，仅改变图表及未排期列表的显示，不写 Jira；排期仍考虑当前完整任务集合，避免遗漏隐藏任务的工时。展开筛选不会撑高整个工具栏。

安装包：`target/filter-gantt-gadget-1.2.1.jar`。通过“管理应用 → 上传应用”更新已有插件，无需重建容器。实际配置可使用本实例的 Target start (`customfield_10109`) 与 Target end (`customfield_10110`)，也可以结束字段选截止日期；这些 ID 仅适用于本实例，其他实例应按字段名称选择。

自动化日志与最终包检查存放于 `validation/*1.2.1*`。真实 Jira 验证范围记录在本文件后续条目；自动化模拟结果不等同于全部生产场景验收。

验证结果：58 项后端测试、16 项前端单测和 24 项最终 JAR 压缩资源浏览器回归全部通过。安装包 963938 字节，SHA-256：`955D01B9DB6487176F11DBDAA7AFBC8F37AD5442A4A6FCB85239938B0A991B9D`。

本地 Jira 已核对实际日期字段、旧配置失效现象及 Portfolio 日期实现。按用户要求，上传由用户自行操作；本次未上传新包、未更改仪表盘字段映射、未修改真实 Jira 任务。真实实例更新及排期写回仍待验证。

## QA 说明

产生原因: 日期类型白名单漏掉 Target start/end, 导致合法排期字段被判只读; 旧日期映射缺少明确修复入口. 人员筛选使用展开式列表, 缺少搜索和状态条件.

解决方案:
1. 补充 Target 日期字段, 统一前后端可写字段范围, 明确旧配置和同字段错误.
2. 失效配置提供修正入口, 显示实际只读原因, 增加可拖动和拉伸标识.
3. 人员和状态采用搜索多选浮层, 条件组合仅控制显示.

测试要点:
1. 原有日期和 Target 日期分别验证拖动, 两端拉伸, 双击编辑及自动排期同步.
2. 验证创建/更新日期, 已删除字段, 相同起止字段, 非所有者, Jira 编辑权限与编辑界面限制.
3. 验证姓名/账号搜索, 状态搜索, 全选, 清空, 空结果, 组合条件及隐藏父任务后的子任务显示.
4. 验证下拉展开不撑高布局, 键盘 Escape 关闭, 多实例隔离和筛选不触发 Jira 更新.

修改清单: 日期字段识别与配置, 甘特编辑提示, 人员和状态筛选, 自动化及安装说明.
